# 画布合成节点的布局归属

- 错误卡片 `err:<nodeId>` 的坐标归属失败节点，和真实节点、产物一起保存在
  `projects/<pid>/hosts/<owner-host>/node-layout.json`。只有所属主机可以修改；
  卡片仅在非 op 节点处于 `error` 且有错误文本时出现。
- context 磁贴以 `ctx:<scope>::<kind>::<path>` 标识，可被多个节点共同引用，
  不归属任何单一节点。坐标保存在项目级共享的 `context-layout.json`，
  独立 `schema_version=1`，通过 `PATCH /sessions/{sid}/context-layout` 更新。
  本机已绑定且可写的项目允许修改，远端只读项目仍可展示坐标。
- 两类坐标都包含 `x`、`y`、`space`。画布使用 `canvas`；泳道内使用
  `planspace:<id>`，坐标相对泳道而非画布。空间不匹配的旧坐标不用于渲染。
- 错误消失、上下文解绑或引用节点删除时不清理持久坐标。重试再次失败，或
  同路径上下文重新绑定时，恢复此前布局；无关位置写入不能删除这些记录。
  显式删除位置仍可通过布局接口的 `remove` 完成。
- 共享 context 布局同步按完整坐标判断冲突，不将两端的 x/y 变更静默拼接。
  同一坐标两端变更不一致、或仅一端删除时，停止合并并报告冲突。
- 方向泳道位置属于可丢弃的界面提示。同步按图元做结构化三方合并；两端同时
  修改或删除同一方向时，以发起合并一侧的位置为准，不能阻塞业务数据同步。
- `tplbox:`、`port:` 不在本次修复范围；`templateGroup` 的几何由成员导出，
  继续不可拖动。
